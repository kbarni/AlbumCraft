# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**AlbumCraft**: a native Rust/egui photo organizer with a simple non-destructive editor, part of the *Craft* apps suite. See `AGENTS.md` for the rules and `new_features.md` for the plan and status.

This directory is the git repository and the Cargo workspace (see Code layout below). The parent directory holds local research notes and generated tool bookkeeping; they are deliberately not in the repository.

## Using it from an agent

Register the MCP server with an MCP client, e.g. for Claude Code: `claude mcp add albumcraft -- /path/to/albumcraft --mcp`. Works with or without the window open.

## Build / run / test

Run from the repository root:

```
cargo build            # dev profile: opt-level 1 for the workspace crates, 3 for dependencies
cargo run
cargo test             # every crate of the workspace; tests are inline #[cfg(test)] modules next to the code
cargo test -p albumcraft-core   # one crate
cargo test <name>      # single test, e.g. cargo test ini_tests
cargo run -- --screenshot out.png   # renders a frame, saves it, and exits (used for `docs/screenshots/`; on a tiling window manager retry until the window is wide)
```

- `rust-toolchain.toml` selects plain `stable` (plus clippy and rustfmt) on every platform. On a Windows machine without the MSVC linker, run `rustup set default-host x86_64-pc-windows-gnu` once; a local, gitignored `.cargo/config.toml` can hold that machine's GNU linker workarounds (paths to `.tools/`, used only for the `x86_64-pc-windows-gnu` target). The `windows` crate is a `[target.'cfg(windows)'.dependencies]` entry (of the app and of the core crate, the same version) and is only used under `#[cfg(windows)]` in `print.rs` (non-Windows has a stub `mod other`) and core's `mail.rs`. `cargo test`: 155 pass, 16 ignored (demos, data converters, network, real-file, real-trash and speed checks).
- CI: `.github/workflows/ci.yml` calls the suite's shared gate (`storytold/craft-common-actions`, `gate.yml@main`) on Ubuntu, Windows and macOS: `cargo build --locked --all-targets && cargo test --locked`. Keep `Cargo.lock` committed and up to date (the gate fails if the build changes it).
- Dev profile deliberately sets `debug = false`, `strip = "debuginfo"`: full debug info produced a 450 MB binary that crashed at startup.
- `ALBUMCRAFT_TRACE=1` prints startup trace lines, how long the scan and `set_library` take, frames over 30 ms (results, geo, the view) and thumbnail arrival. `ALBUMCRAFT_PERF_DIR=<photos> cargo test --release -p albumcraft-core perf_ -- --ignored --nocapture` times decoding, thumbnails (whole folder on 6 threads), the thumbnail cache and import (`perf_import` also needs `ALBUMCRAFT_PERF_DEST`, optionally `ALBUMCRAFT_PERF_LIBRARY`); `perf_raw` needs `ALBUMCRAFT_PERF_RAW=1`; `perf_check_embedded_previews` checks the camera previews against full decodes (`perf_tests.rs`). Measured on 12 MP phone JPEGs from a USB disk: thumbnail 3 ms (embedded preview; 108 ms decoding the picture), 1400 px preview 128 ms, 886 thumbnails in 0.8 s. `ALBUMCRAFT_LANG=fr` forces a language and `ALBUMCRAFT_SHOT_SIZE=900x560` the window's size (a tiling window manager ignores it: run in a nested X server, e.g. `Xephyr :7 -screen 1400x900` and `env -u WAYLAND_DISPLAY DISPLAY=:7 …`), `ALBUMCRAFT_THEME=light|dark` forces a theme and `ALBUMCRAFT_SHOT_VIEW=edit|presets|effects|slideshow|viewer|settings|export|movie|print|compare|props|zoom|tray|map|place|pin|maps|geometry|import|search|mapscope|crop|collage|sheet|rescan|scroll|notices|dialog|recrop|sort|cached|open|trash` picks the view for `--screenshot` (`collage`: 12 pictures in a photo pile, or the style named by `ALBUMCRAFT_SHOT_STYLE=pile|mosaic|centre|grid|film|clothesline|fan|shape|blend`; `sheet`: the contact sheet; `viewer`: the full-screen viewer started from the third picture in the editor; `export`: the Export view with six pictures (one left out), a text signature, creator and copyright; `settings`: the Settings dialog at the section named by `ALBUMCRAFT_SHOT_SECTION=interface|folders|editing|slideshow|export|maps|storage|ai`; `import`: the import view with the sample pictures as a card, `search`: the search box with a chip and suggestions, `mapscope`: one folder on the map, `scroll`: the library with large pictures, scrolled to the last one, `rescan`: a scan that finds one folder less while the editor is open, printing `rescan check: kept` when the open picture and the selection survive, `crop`: the crop tool with a 3 × 2 box, `geometry`: also shows the alignment grid, `map`: Places with sample locations, `place`/`pin`: Set location, `maps`: the online-maps question, `sort`: highest rating first, printing `sort check: ok`, `cached`: the catalogue cache shown before the first scan and not after it, printing `cache check: ok`, `open`: three pictures selected and one opened, printing `open check: kept` when the editor steps through those three and the selection stays, `trash`: the question before rejected pictures go to the trash); `ALBUMCRAFT_SHOT_ONLINE=1` shows OpenStreetMap tiles in the map shots (downloads them; the screenshot waits for them).
- Windows without the MSVC linker (this machine): `$env:Path = "C:\msys64\ucrt64\bin;" + $env:Path; cargo +stable-x86_64-pc-windows-gnu test` (MinGW from MSYS2 provides `dlltool`). Edit files with the editor, not PowerShell 5.1 `Get-Content`/`Set-Content` (they mangle UTF-8).
- Release builds set `windows_subsystem = "windows"` (no console).

## Code layout

A Cargo workspace (edition 2024) of three crates, split so that a planned server (Docker) and browser (WebAssembly) version can share the code:

- `crates/albumcraft-edit` — the edit pipeline only (`imaging`, `develop`, `looks`, `decor`): pictures in memory, no file access, no threads of its own. Builds for `wasm32-unknown-unknown` (`cargo build -p albumcraft-edit --target wasm32-unknown-unknown`); keep it that way.
- `crates/albumcraft-core` — everything without a window: `library`, `catalogue`, `commands`, `mcp`, `control`, `exifinfo`, `raw`, `geo`, `thumbcache`, `export`, `gallery`, `movie`, `collage`, `msg` (translatable messages), `locale` (date / number / size formats), `online` (services), `print` (layouts, PDF writer), `slides` (settings). Re-exports the edit crate's modules; its `imaging` adds file loading (`load_source`, `oriented_dims`) to the pipeline.
- `albumcraft` (the root package, `src/`) — the egui app. `main.rs` re-exports the core modules (`pub use albumcraft_core::{library, imaging, …}`), so app code keeps writing `crate::library::…`. Its `online.rs`, `print.rs` and `slides.rs` glob-re-export the core module of the same name and add the window's part (tile textures, printers, music).
- `src/backend.rs` — the `Library` interface between `App` and the pictures: load / save the notes, scan folders, read / write the catalogue cache, thumbnail / preview / zoom jobs, picture sizes, EXIF, file GPS and the GPS index, `.picasa.ini`, a picture reader for print and collage, export, web gallery, movie, collage / contact sheet files. Slow answers come back as `library::Done` on `App.rx`. `LocalLibrary` is today's behaviour (folders on this computer, `library.json`, the `Pool`); a remote library can implement the same trait. `App` and the views must not read files themselves.

## Architecture

Single-window eframe/egui app. `main.rs` parses `--screenshot` / `--mcp` and runs `app::App`.

- `display.rs` — on Linux/BSD, asks winit for X11 when `WAYLAND_DISPLAY` points to a socket that does not exist (a variable left over from a Wayland session; winit would otherwise fail with "NoCompositor"). Uses the `winit` crate directly (same version as eframe's).

- `app.rs` — the `App` struct (all UI state: catalogue `Store`, its `lib: Box<dyn Library>`, photos/folders, texture caches, selection (`App::tray`: the selected pictures, or a clicked folder / album / person as a whole), edit state, slideshow, print state, dialogs) and the `eframe::App::update` loop. `View` selects Library / Edit / etc.; `Dialog`, `Tool`, `Tab`, `CompareMode` enumerate modes. Also theme setup and screenshot capture.
- `dialogs.rs` — the dialogs (`App::dialogs`, one `Dialog` at a time, an `egui::Modal`: Esc or a click beside it cancels, Enter presses the main button of the simple ones) and the notices (`App.notices`, stacked over the bottom of the window): `App::toast` (a short note), `App::error` (stays until closed; a failed save is one), `App::undoable` (with an Undo button for 8 s: deleting an album, removing a library folder, the menu's Undo all edits; `Undo` / `App::undo_action`) and the results of background work with Show in folder. **Background work the user waits for is a task**: `App::start_task(label)` gives a `backend::Task` (number + stop switch) passed to `Library::export` / `make_gallery` / `make_movie` / `make_collage`; progress comes back as `Done::Progress`, the end as `Done::Report` (`library::Report`: text, ok or failed, a path to show); the status bar shows each task with a progress bar and Cancel. Stopped work returns `library::STOPPED` from `gallery::write` / `movie::make` and removes what it had made. `demo.rs` — `App::demo_setup`: the fixed sample state behind `--screenshot` and the view picked by `ALBUMCRAFT_SHOT_VIEW`. `slideshow_view.rs` — the full-screen slideshow (`View::Slideshow`) and its control bar. The editor's full-screen button (or F11) starts it as a viewer (`App::start_viewer`): from the current picture, no fade or motion, advancing by itself, music on when a file is chosen; each showing has its own `Slideshow.settings`, and the viewer saves only the interval and music file back to `Store.slideshow`. F11 or Esc leaves. `settings_view.rs` — the Settings dialog (`Dialog::Settings`, ☰ menu or Ctrl+,): the sections listed on the left (Interface, Folders, Editing, Slideshow, Export, Maps, Storage, AI features), the chosen one on the right, in a box of fixed size (inside a modal, separators and scroll areas would otherwise grow without end). Changes apply and are saved at once. It changes the same saved values as the other places that have them (theme button, slideshow bar, Export view), plus `Store.bar_style` (the bar at the bottom of the library: compact or tray, see shell.rs), `Store.edit_advanced` (the Edit tab opens on Advanced when the editor is entered), `Store.export_size` / `export_quality` (what the Export view starts with), `Store.export_exif`, `Store.export_creator` / `export_copyright`, `SlideSettings.auto_advance` (off: pictures change only with → or the buttons; the viewer always advances, movies always do) / `captions` / `strong_motion` (pan and zoom 25 % instead of 15 %, also in movies). Cache sizes and emptying go through `Library::cache_sizes` / `clear_cache` (`Done::CacheSizes`; `library::cache_sizes` / `clear_cache`).
- `library.rs` — the catalogue data model (`Store`, `Meta`, `Album`, `Folder`, `Photo`), JSON persistence, `.picasa.ini` import, folder scan, and the background loader `Pool` (worker threads fed by two `Job` queues: urgent first, newest first in both, so what is on screen now comes before what scrolled away; returning `Done` messages over an mpsc channel and calling a `Wake` callback; thumbnails at 256 px (`THUMB_DIM`; 512 px, `SHARP_THUMB_DIM`, for grid tiles larger than that in screen pixels: `App::want_sharp_thumb`, asked for once the usual one is shown, counted four times in `trim_thumbs`), "big" at 1400 px, sharp zoom render up to 5000 px with edits applied).
- `catalogue.rs` — the catalogue cache (`cache_dir()/AlbumCraft/catalogue.json`): the folders and files the last scan found (path, date, size) and what was read from each header since (shape, date taken: `read_details`). `App::new` asks for it (`Library::cached` → `Done::Cached`) before the scan and shows it at once; the scan's `Done::Scan` then replaces it (`keep_across_scan` keeps what is known about unchanged files) and a cache arriving after it is ignored (`App.scanned`). `App::save_catalogue` writes it at most every 30 s while it grows and when the window closes (`Catalogue::of`; ~40 ms on the window thread for 200,000 pictures, read in 0.3 s: `perf_catalogue`). Only a cache: damaged or of another `VERSION`, it is ignored; it never holds notes.
- `thumbcache.rs` — on-disk thumbnail cache in `dirs::cache_dir()/AlbumCraft/thumbs`, keyed by path, mtime, size and thumbnail size.
- `theme.rs` — light/dark colour tokens (`t()` returns the active `Tokens`; never hard-code UI colours in views) and the egui style built from them. Mode (system/light/dark) is saved in `Store.theme`, resolved each frame in `App::logic`, and cycled by the theme button in the top bar. Paper sheets in print preview and overlays drawn on top of pictures intentionally stay white/dark in both themes. `set_fonts` adds the bundled Hack font as a fallback for ordinary text and the Material Symbols icon font last. Every character in UI text must be in the bundled text fonts (Ubuntu Light, Hack) or the icon font; emoji are not used (they come from each system's font and look different everywhere). The test `every_ui_character_is_in_the_fonts` enforces it.
- `i18n.rs` — the interface's languages (Fluent, `i18n-embed`): `i18n/<code>/albumcraft.ftl`, built into the program; English (`i18n/en`) is the reference and the fallback for a missing message. UI text is written `tr!("message-id")` or `tr!("id", n = count)` (ids and argument names are checked against the English file at compile time; every argument must appear in the English message; arguments must be plain variables, not expressions such as `n + 1`; plurals as `{ $n -> [one] … *[other] … }`, never `if n == 1`; a message that starts or ends with a space needs `{ " " }`, since Fluent trims it). **New UI text goes in `i18n/en/albumcraft.ftl` and in every other language's file** (`languages_have_the_english_messages` fails otherwise; untranslated, copy the English). The language is `Store.language` (empty = the system's), chosen in Settings > Interface and applied at once (`set_language`); `ALBUMCRAFT_LANG=fr` overrides it (also for `--screenshot`); tests always read English. The font test checks the `.ftl` files too. `labels.rs` gives the window's names for values of the edit and core crates (looks, edit steps, white balance presets, collage styles, page formats, print layout and quality, import summary): those crates keep English `label()`s and have no language. Translated: everything in the window's own code (every view, dialog, notice and the reports of background work in `backend.rs`). **Text made in the core crate** is `msg!("key", "English with {name} and {n:one|other}", name = value)` (core `msg.rs`): the English stays at the place that makes it (it is what `--mcp`, tests and a missing translation show), `String::from` / `.into()` / `?` / `.to_string()` write it in the window's language through the translator `i18n::init` installs, and `en.ftl` must hold the same English under the same key (`core_messages_match_the_english_file` compares them; `languages_use_the_english_arguments` checks every language's `$arguments`). Texts for agents (`commands`, `mcp`, `control`), the system's own error texts (`e.to_string()` of io errors) and EXIF values (`exifinfo`, from the exif crate) stay English. **Dates, numbers and sizes** go through the core crate's `locale.rs` (`Locale`: month names, date pattern, decimal and group separators, KB/MB/GB; English until the window sets it): `i18n::set_language` builds it from the `locale-*` messages, so `library::fmt_date`, `fmt_bytes`, `exifinfo::trim_num` and `app::fmt_count` follow the language; a number formatted by hand for the screen goes through `locale::decimal`. **Scripts and layout:** Chinese, Japanese and Korean use a font of the system (`i18n::script_font_candidates`: Noto CJK, then the Windows and macOS ones; not bundled), added by `theme::set_fonts`, which runs after the language is chosen and again when it changes; the font test skips those languages' files. Right-to-left languages (Arabic, Hebrew) are not supported (egui does not lay them out). Longer languages are checked at the smallest window (900 × 560): the library's title is cut short and its search box takes what the buttons leave, the Folders button is icon only when narrow, the editor's bottom bar leaves out the rotate buttons and the zoom slider, and the Places bar's text wraps; new bars must do the same rather than assume English widths. Shared words (`button-ok`, `button-cancel`, `add-folder`…) are at the top of the file.
- `icons.rs` — the UI icons: named constants for Material Symbols characters (`icons::EXPORT`…), mixed into text with `format!`. The bundled font (`assets/fonts/`) holds only these; adding one means rebuilding it (`assets/fonts/README.md`). `every_icon_is_in_the_icon_font` checks them.
- `shell.rs` — the Library UI: top bar (search pill, Picks chip, rating/reject filter chip, sort menu (`Store.sort`: file name (albums as arranged), date taken, rating; `App::sort_groups`), size slider, theme toggle, Folders (folder manager), Import (import view)), sidebar (app title with the ☰ menu button, Picks, albums/people/folders), justified-row photo grid (aspect-preserving, check circle + pick flag on hover; pick flag, rating stars and a dimmed reject mark shown on tiles), selection bar and status bar at the bottom. Only what is in view is laid out and drawn: the rows are kept in `GridCache` (`App::grid_rows`, made again when the list, the width, the picture size or a shape (`App::shape_rev`) changes) and folders and rows out of sight are empty space of their height; the sidebar's counts come from `App::sidebar_counts` (once per `list_rev`), the list itself from `App::groups` (shared, `Rc`), and typed text is searched in `App::search_hay` (one lower-case string per picture, kept until notes or places change). The grid never reads files: shapes and dates taken come from `Job::Dims` (one batch of 128 at a time, walking the list once; `App.real_dims`, `App.taken` (the file's date when there is no EXIF date); the order by date is made again at most once a second while they arrive, `taken_rev`), and so does the status bar's date (no EXIF read on the window thread); thumbnail jobs waiting beyond 1000 are forgotten oldest first (`Done::Dropped`) and asked for again when drawn; at most 1200 thumbnails are kept (`App::trim_thumbs`, least recently drawn go first; views call `want_thumb`) (`library_view::selection_bar` / `status_bar`). **Selecting:** click, Ctrl+click, Shift+click; a drag on the background draws a box that selects what it touches (`App.box_select`; Ctrl or Shift adds to the selection; the grid scrolls near its edges); arrows move (up and down by the rows' real layout, `grid_step`), Shift+arrows extend from where the selection started (`App.anchor`, `App.cursor`), Home / End, Space or Enter opens; the grid scrolls only as far as needed (`App.reveal`). Pictures dragged from the grid (`DraggedPictures`: the selection, or the one dragged) drop onto an album in the sidebar. **The bar at the bottom** is the compact selection bar or the tray (`Store.bar_style`, chosen in Settings; `library_view::selection_bar`; `ALBUMCRAFT_SHOT_BAR=tray` for screenshots). **The tray** (`TRAY_H`, always shown, `tray_bar`): a well with thumbnails of the selected pictures (the first ones, then "+N"; a small pile for a folder / album / person selected as a whole), To album and Clear, pick / reject / stars, rotate / tags / location, and tall buttons (`big_button`, 62 × 60) for Web page, Email, Print, Export, Collage, Movie; it scrolls sideways when narrow. **The compact selection bar** (`SELECTION_BAR_H`) is shown only while something is selected: what is selected and Clear, pick / reject / stars, rotate, tags, location, To album, then Web page, Email, Print, Export, Collage, Movie on the right; below ~1180 pt the buttons lose their labels, and when it still does not fit it scrolls sideways (nothing overlaps). There is no Hold: the selection is what actions apply to. Opening a picture with several selected keeps the selection and the editor steps through those (`open_editor`; a double-click brings back the selection its first click replaced, `App.before_click`). **Rejected pictures to the trash:** the ☰ menu and the rating filter's menu (`App::ask_trash_rejects`, `Dialog::TrashRejects` (no Enter), `Library::trash` → `library::move_to_trash` with the `trash` crate; in a Flatpak, files on the home disk go to `~/.local/share/Trash` by hand (`into_home_trash`), since the sandbox's `XDG_DATA_HOME` would hide them; the library is scanned again after, `App.rescan_after`); the one place where original files are removed, after a confirmation, to the system's trash. The app menu behind the ☰ button is one flat list, without submenus per topic (`library_view::app_menu_items`).
- `search_box.rs` — the library's search box (`App::library_search`): typed text matches names, captions, tags, people and places anywhere; the dropdown suggests tags, places, people (`SearchTerm`, chosen ones become chips that match exactly, all must match), albums and folders (open them), with picture counts from a cached `SearchIndex`. ↑/↓, Enter, Esc, Backspace removes the last chip. Places come from `GeoState.place_terms` (`geo::place_terms` per located picture: the name set, the nearest city within 60 km, its region and country; refreshed only for pictures whose position or name changed).
- `library_view.rs` — shared library helpers: `paint_star`, key handling (`library_keys`), the selection bar and status bar, the menu items and the per-picture context menu (`cell_menu`).
- `mail.rs` (core) — Email: small copies (1200 px, `export_one`; named without commas, quotes, backslashes or spaces, `attachment_stem`, since xdg-email gives Thunderbird the attachments as one comma-separated list) in a new folder under the temporary folder (`new_folder`; folders older than a day are removed), then a new message in the mail program with them attached (`compose`): `xdg-email --attach` on Linux / BSD (attaches for Thunderbird, Evolution, KMail), Simple MAPI on Windows (`MAPISendMailW` looked up in `mapi32.dll`: classic Outlook, Thunderbird), `open -a Mail` on macOS. Nothing is sent: the user addresses and sends it. When no mail program can be asked, the report says where the copies are, with Show in folder (`email`; the window's `App::email` via `Library::email`, and the `email_pictures` command). Tests never call `compose` (it would open the mail program).
- `edit_view.rs` — editor UI. Tabs: **Edit** (Basic: one-click fixes and tools; Advanced: Geometry first (Crop… / Remove crop, straighten, perspective; a square alignment grid (about 15 cells on the long side) shows on the picture while those sliders move, `edit.grid_until`), then the sliders), **Presets** and **Effects**. **One adjustment, one look, one straighten, one perspective and one crop per picture**: the panels change those steps where they stand in the edit list (`steps.rs` in the edit crate: `set_adjust`, `set_look`, `set_geometry`, `set_crop`; the saved format is still the list of `EditOp`, older lists with several steps of a kind keep working, the last one is the one edited). Every change goes through `App::change_edits(id, gesture, …)`, which keeps the list as it was for **Undo** (`EditState.undo` / `redo`, whole lists; one step per slider movement: changes with the same `gesture` name until the mouse button is let go; Ctrl+Z, Ctrl+Shift+Z or Ctrl+Y; a click on a step in the list goes back to it). The **crop tool** shows the picture uncropped (`steps::crop_view`) with the box it has, to change by its edges, corners or inside (`steps::grip_at` / `drag_box` / `drawn_box`, which keep a fixed shape against the picture's edges); Enter applies. **Original** (button, or O / \\ held) shows the picture without edits; **Compare** shows two pictures side by side (the two-version before/after mode is gone). A double-click on the picture toggles Fit and 100 %. The preview keeps the picture as it is before the step being changed (`BigEntry.stage`), so a slider re-applies only its own step and the later ones; thumbnails of edited pictures are made again when next drawn, a few per frame (`App::refresh_thumb` / `stale_thumbs`); crop/straighten/red-eye/pick-neutral tools draw on the single view (crop: free, original shape, square, 4 × 3, 3 × 2, 16 × 9 (a drop-down), landscape or portrait orientation; a chosen shape starts as the largest centred box; drag inside to move it; thirds lines); compare modes; histogram with clipping warning.
- `info_panel.rs` — the editor's info panel (Info button or I; shown by default, `Store.info_open`): foldable sections remembered in `Store.info_sections` — Properties (camera, date taken, size, file, lens, focal length, aperture, exposure, ISO, folder, edits), Extended EXIF (closed at first; the rest, the camera preview, all EXIF entries), Location (`App::mini_map` from map_view: built-in map or online tiles, pin; Modify… opens Set location, the map or Show on map opens Places) and Tags (chips, add field with suggestions from the library's tags, `suggest`). People stay in the editor's bottom bar until faces exist.
- `looks.rs` — preset looks (`Look`: vivid, soft film, instant, cross process, lomo, matte, teal & orange, high key, cool, warm, B & W, dramatic B & W, sepia, soft focus, glow, film grain, focal B & W) as `EditOp::Look { look, amount }`: the full look blended with the picture by intensity. Choosing a look right after another replaces it (`set_look` in edit_view).
- `steps.rs` (edit crate) — the rules for changing an edit list the way the editor's panels do (see `edit_view.rs`), with tests; no window code.
- `decor.rs` — the Effects tab: `Decor` (vignette, border / instant frame, drop shadow, rounded corners, text with anchor, size, colour and halo) as `EditOp::Decor`; sizes are fractions of the picture so preview and export match. The Effects tab edits the last step when it is the same kind; the add buttons always add a new step. Older one-click `EditOp::Effect` steps still render (several are reused by presets).
- `develop.rs` — `Adjust` (white balance, exposure, highlights, shadows, blacks, contrast, saturation, vibrance, clarity, sharpen, noise reduction; rayon-parallel, radii scale with picture size) and the analysis behind the one-click fixes (`auto_exposure`, `auto_white_balance`, `lucky`, `neutralize`, `auto_straighten`). `cargo test --release develop_speed -- --ignored --nocapture` times it (release, 20 cores: preview 1400 px ~10 ms tone/colour, ~90 ms with all detail sliders; 24 MP ~1.2 s).
- `imaging.rs` (core) — reading pictures: `jpeg_head` / `jpeg_head_of` (size, orientation and EXIF from the first segments only; decoders read the whole file), `embedded_preview` (the camera's preview, used when at least as big as asked and the same shape), `load_thumbnail` (embedded preview, else `load_source`), and scaled JPEG decoding with `jpeg-decoder` (1/2, 1/4, 1/8) when the target is at most half the picture.
- `imaging.rs` — non-destructive edit pipeline (edit crate): `EditOp` / `Effect` applied on the fly by `apply_all`; built-in sample images (keys prefixed `SAMPLE_PREFIX`, `sample_source`) used when no real folders are scanned. Image loading (`load_source`, `oriented_dims`) is core's `imaging.rs`.
- `import.rs` (core) — importing (copying from a card, camera or folder into one new folder; adding a folder copies nothing): `list` (pictures of a source with EXIF dates, oldest first, `duplicate` when the library has the same content: same size, then a fingerprint of the first and last 64 KB), `groups` (split at 2 h gaps), `suggested_name`, `check_folder_name`, `removable_sources` (Windows drives with DCIM; `/media/$USER`, `/run/media/$USER`, `/Volumes`), `copy_into` (never overwrites: taken names get " (2)", identical files are skipped; temp file then rename; keeps the file date; stoppable).
- `import_view.rs` — `View::Import`: source picker, thumbnail grid by time group (tri-state group checkboxes, check circles, duplicates hidden or tagged), preview panel, destination folder + new folder name, one Import button. The copy runs in the background (`Library::import`, progress in the status bar with Stop); the destination is then added to `Store.roots` if no root covers it, rescanned and shown (`App::show_imported_folder`). `Store.import_to` remembers the last destination. Thumbnails come from `Job::File` (any file by path, not a library id).
- `export.rs` (core) — `export_one(key, edits, dir, stem, &Options, gps, logo)`: an edited JPEG copy, never overwriting a file. `Options` (`Store::export_options`): size, quality, the original's camera information (`Store.export_exif`, `exifinfo::fields_to_keep`: camera, lens, exposure, dates, author; not orientation, pixel sizes, thumbnails, maker notes or GPS), creator and copyright (EXIF Artist / Copyright, replacing the original's), and a `Signature` (`Store.export_signature`: text or logo file, anchor 0…8, size as a fraction of the shorter side, opacity, colour, halo) drawn after the edits by `sign` (text through `decor`'s text step, faded with `decor::blend`; a logo with `decor::stamp`, read once per export by `load_logo`). The GPS position is added when `Store.export_location`. Email copies use the same camera information, creator and copyright, never a signature; the `export` command takes `include_camera_info`, `creator`, `copyright`.
- `export_view.rs` — `View::Export` (the Export buttons of both bars, the context menu and the editor; `App::open_export`): the options on the left quarter (size incl. other, JPEG quality, signature with a 3 × 3 position picker, GPS, camera information, creator, copyright), the pictures on the right with the signature drawn on each thumbnail as `sign` will draw it (`paint_signature`, the logo as a texture via `Job::File`) and a click leaving one out, the folder (`Store.export_to`, else the Pictures folder) and Export at the bottom; `Library::export` does the work as a task. The signature, creator, copyright and the two EXIF switches are saved; size and quality start from Settings each time.
- `raw.rs` — camera raw files (CR2, CR3, NEF, ARW, DNG, ORF, RW2, RAF…) shown through their largest embedded JPEG preview, turned by the raw file's EXIF orientation; `imaging::load_source` / `oriented_dims` route raw files here. Embedded JPEGs are found by their header only (no decoder copies) and decoded at a reduced scale when possible (`preview_scaled`). No sensor-data developing. `ALBUMCRAFT_RAW_SAMPLE=<file> cargo test real_raw_file -- --ignored --nocapture` checks a real file.
- `slides.rs` — slideshow settings (`Store.slideshow`: seconds per picture, crossfade, pan-and-zoom motion, music file), `ken_burns_uv` / `fade_in` (shared with the movie export) and `Music` (rodio, looping; Linux builds need the ALSA headers, `libasound2-dev`).
- `gallery.rs` — web gallery: a new folder (never an existing one) with `images/`, `thumbs/` and a self-contained `index.html` (inline CSS + lightbox script; light grid, dark grid or masonry). Captions and titles are HTML-escaped and the lightbox data is JSON with `<` escaped. `ALBUMCRAFT_GALLERY_OUT=<dir> cargo test demo_gallery -- --ignored` writes demos.
- `movie.rs` — movie export: frames rendered with the slideshow's timing (`at_time`), crossfade and pan-and-zoom, piped as raw RGBA to the `ffmpeg` program (H.264 if available, else MPEG-4; looped music muxed with `-shortest`). Needs FFmpeg on the PATH; the Movie dialog says so when it is missing. The test makes a real short movie when FFmpeg is installed and skips otherwise.
- `geo.rs` — locations: `LatLon`, `Place` (`Meta.place`: `Set { lat, lon, name }` overrides the file's GPS, `Removed` hides it; `effective` combines them), typed-coordinate parsing, EXIF GPS reading (`file_gps`, `gps_of`) and writing for exports (`exif_gps_fields`), the background GPS index with its cache (`index_files`, `cache_dir()/AlbumCraft/gps.json`), the built-in GeoNames city list (`assets/geo/cities.bin`: `search`, `nearest` (latitude-sorted index, microseconds), `describe` → "Near Bordeaux, France", `place_terms`) and the Web Mercator projection (`to_world`/`from_world`). The data converters are ignored tests (`assets/geo/README.md`).
- `basemap.rs` — the built-in world map (Natural Earth land, lakes, borders in `assets/geo/basemap.bin`), triangulated once with `earcut` on a background thread (`basemap::get`), drawn with the `map_*` theme tokens.
- `online.rs` — online maps, only when `Store.online_maps == Some(true)` (asked once at the first start, `Dialog::OnlineMaps`): OpenStreetMap tiles (2 download threads, only tiles in view, disk cache `cache_dir()/AlbumCraft/tiles` fresh 14 days, 500 MB cap, textures LRU) and Nominatim search / reverse lookup (≥ 1 s apart, on demand only). `ureq` with rustls. `cargo test online_services -- --ignored` talks to the real servers.
- `map_view.rs` — `View::Map`: the Places map (clustered photo markers, selection strip, search box with built-in and online results) and "Set location" mode (the tray's location button next to Tags, the context menu, Properties), and a scope (`MapScope`: a folder, an album or the tray only, by key; `App::show_set_on_map` from the folder header's map button and the album's menu; "Show the whole library" drops it; the sidebar's Places always shows everything) (`App::start_placing`: search or click to drop a pin, drag it, name it, apply / remove). `GeoState` (in `App.geo`) holds the GPS index results (`file_gps`, keyed by path), the cached located list and the map state. `Viewport` does the screen ↔ world math and repeats the world across the date line.
- `commands.rs` — the command layer: 33 named commands with JSON-schema parameters (search, also by `tag`, `place` (city, region, country, also from the file's GPS), `has_location` / `near`, flag, rating, caption, tags/people, albums, add folder, `import_pictures`, `rescan`, edit steps, auto fixes, undo, copy edits, `render_preview` returning a PNG, export (with the location in EXIF), web gallery, movie, `make_collage`, `make_contact_sheet`, show in editor, `show_on_map` (a set of pictures on the window's map), `set_location`, `remove_location`, `find_place`, `set_sort_order`, `email_pictures`, `trash_rejected` (only rejected pictures, only with `confirm: true`)). The UI calls `set_place` / `remove_place` too. They run on a `Host`: the window (`App`, impl at the end of app.rs) or `Headless` (library.json without a window). Pictures are named by key (file path). Slow commands return `Outcome::Later` (a closure run off the UI thread). Bad parameters are `Err`, never panics (`bad_input_is_an_error_not_a_crash`).
- `mcp.rs` — `albumcraft --mcp`: MCP server (JSON-RPC 2.0, one message per line on stdin/stdout; `initialize`, `tools/list`, `tools/call`, `ping`). Each call goes to the open window through `control.rs` when there is one, otherwise to a `Headless` library that is reloaded before and saved after each changing call. Nothing but protocol messages may be written to stdout in this mode.
- `control.rs` — the window's control connection: 127.0.0.1 on a free port, a random 256-bit token, both in `<data dir>/AlbumCraft/control.json` (mode 0600, removed when the window closes); one JSON line per request, 1 MB limit, 4 connections, wrong token closes the connection. The window runs requests in `App::run_control_requests` each frame.
- `exifinfo.rs` — EXIF/camera info and embedded thumbnails (kamadak-exif).
- `collage.rs` (core) / `collage_view.rs` — collages and contact sheets. Core: `Style` (photo pile, mosaic, centre stage, grid, film strip, clothesline, fan, shape (heart / circle / star), multiple exposure), `collage()` and `contact_sheet()` lay pictures out as `Shape`s on a `Page` in millimetres (pictures as `PhotoShape` cards with frame and shadow, rectangles, lines, text); `render` draws a page into pixels (rotated pictures, soft shadows, gradients, blurred picture backgrounds, text with the UI's font); `save` writes a PDF (`print::pdf_of_pages`, 200 dpi) or one JPEG / PNG per page; `on_paper` fits a page on a printer's paper. Settings in `Store.collage` / `Store.contact_sheet`. The view (`View::Collage`, tray Collage button, menu Contact sheet…) draws the same shapes with the thumbnails as its preview: style tiles drawn from the real layouts, background colour / gradient / picture (a collage picture or any file, via `Job::File`), page size, drag to swap pictures (pile: drag to move, scroll to turn, `Nudge`), Delete leaves the selected one out; Save picture / Save as PDF go through `Library::make_collage`, Print renders on a thread like the print screen. `ALBUMCRAFT_COLLAGE_OUT=<dir> cargo test -p albumcraft-core demo_collages -- --ignored` writes every style and a contact sheet.
- `print.rs` / `print_view.rs` — print layouts, paper/borders/captions; printing through Win32 GDI on Windows and through CUPS on Linux/macOS (`print.rs` `mod cups`: `lpstat`/`lpoptions` for printers, paper sizes and resolution; the pages go to `lp` as a PDF written by core's `print::pdf_of_pages`, JPEG pages placed on the printable area, 5 mm margins). `print::available()` hides every print entry point when neither works (no CUPS scheduler). Tests never send a job: they write the PDF to a file (`ALBUMCRAFT_PDF_OUT=out.pdf cargo test cups_pdf_demo -- --ignored` for a sample).

Key design rules:
- **Originals are never modified.** Edits, stars, captions, tags, people, albums are stored as `Meta` in `library.json` under the user data dir (`dirs::data_dir()/AlbumCraft/library.json`, see `library::store_path`; a library saved under the earlier working name `PhotoShelf/` is copied over on first start). Photos are keyed by file path string.
- **`library.json` has a format version** (`Store.version`, `library::FORMAT_VERSION`). A library saved by a newer version is never saved over (`Loaded::Unreadable` with no backup: the window does not save, `--mcp` refuses it), even when this version can't parse it. Settings that a newer version may extend are read with `or_default` (an unknown value becomes the default, not an unreadable library).
- **Locations:** `Meta.place` (see `geo.rs`); the file's own GPS is read by the background index, never written. Exports carry the location in EXIF when `Store.export_location`. No network unless `Store.online_maps == Some(true)` (only `online.rs` connects).
- **Culling:** `Meta.flag` (`Flag::None/Pick/Reject`) and `Meta.rating` (0–5). Keys P / X / U / 0–5 act on the selection (library) or the current picture (editor); `library_view::flag_rating_menu` / `flag_rating_keys`. The yes/no `star` of older libraries and `.picasa.ini` `star=yes` become picks (`Meta::upgrade`, on load).
- **Copy / paste edits:** `App::copy_edits` / `paste_edits` (Ctrl+Shift+C / Ctrl+Shift+V; plain Ctrl+C/V reach egui as clipboard events, not keys). Pasting appends the copied ops (red-eye fixes excluded, `copyable_edits`) to each picture's own edits.
- **`.picasa.ini` files are read once per folder and never written** (tracked via `Store.imported_ini`). The scan thread reads them (`Library::scan`, sent with `Done::Scan`); `App::import_picasa_ini` only merges.
- **A scan keeps the window's state.** `App::set_library` rebuilds `photos` / `folders`, then `keep_across_scan` moves the selection, the open picture, the keyboard's place, print, collage and slideshow pictures to their new ids by file path, and keeps thumbnails and previews of unchanged files (same date and size). Sample pictures are shown only when the library has no folders; folders that can't be reached give an empty library with Scan again / Folders buttons. Notes on sample pictures are never written to `library.json`.
- All decoding/rendering goes through the `Library` (`LocalLibrary` → `Pool`); UI code requests via `Job`s (`App.lib.request`) and consumes `Done` results each frame (textures are cached in `App` maps keyed by photo id).
